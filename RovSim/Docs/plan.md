# 0. 总原则（贯穿所有阶段）

## 0.1 交付物定义

- **可运行**：按步骤操作能得到一致结果（稳定启动/停止、UI可用、图表能出数据）。
- **可观测**：所有关键物理量可实时看到（面板）+ 可连续看到（曲线）+ 可回溯看到（记录/回放）。
- **可对比**：不同设计（推进器布局/重心/浮心）造成的运动差异明确可见。
- **可演示**：有预设方案、一键加载与清晰的展示路径（新用户 3 分钟内看到“专业感”）。

## 0.2 基础工程规范（建议在实现时统一）

- 数据通道统一：仿真核心只产出状态；UI/记录只消费状态。
- 单位统一：长度 m、速度 m/s、角度 rad（UI显示转°）、力 N、力矩 N·m、时间 s。
- 频率策略：物理步进与采样频率解耦（例如物理 60Hz；记录/图表 10/50Hz）。
- 性能策略：图表做下采样/滑动窗口，避免每帧全量重绘。

# 1. Phase A：现状盘点与接口冻结（P0 前置）

## 1.1 目标

- 把“仿真核心输出什么、UI消费什么”这条线先钉死，避免后面反复返工。

## 1.2 任务清单

- [ ] 代码结构快速巡检：Runtime Builder / Assembler / Simulation Core / Sensor Layer / UI 的现有脚本入口、节点层级与数据流
- [ ] 定义并实现一份稳定的状态快照结构（ROVState + ThrusterState）
- [ ] 明确一个“全局时钟/仿真时间”来源（simulation_time），供记录与图表统一使用

## 1.3 验收标准

- 在任意时刻能拿到一个 ROVState（位置、速度、姿态、角速度、深度），并能打印/显示一帧快照用于调试验证。
- 状态结构字段、单位、坐标系约定写在 plan.md 本节内（见 1.4）。

## 1.4 状态结构（建议）

- **ROVState（快照）**
  - time_s
  - position_m（Vector3）
  - linear_velocity_mps（Vector3）
  - rotation_quat（Quaternion）
  - angular_velocity_radps（Vector3）
  - depth_m（float，约定：向下为正或向上为正，需统一）
- **ThrusterState（数组）**
  - id / name
  - command（归一化 -1..1 或目标推力，需统一）
  - thrust_n（float）
  - efficiency（可选）

# 2. Phase B：P0 收口（“系统像回事”）

> 你在 target.md 里写的 P0（拼装/仿真/基础状态）如果已经完成 70~80%，这个阶段的目标是“补齐缺口 + 可演示的一条主路径”。

## 2.1 Runtime Builder（拼装工具）收口

### 任务清单

- [ ] 添加 Part：推进器等核心部件可添加、可重复添加
- [ ] 选择/高亮：鼠标/列表选择一致
- [ ] 移动/旋转：有明确的操控方式（gizmo 或快捷键），支持局部/全局坐标（至少一种）
- [ ] 删除 Part：撤销（可选）、至少支持删除当前选中项
- [ ] Inspector 参数编辑：推进器方向/推力上限/安装偏移等关键参数可编辑并即时生效
- [ ] 推进器方向可视化（建议）：箭头或线段，能一眼识别朝向
- [ ] 重心/浮心可视化（建议）：点或小球 + 标签

### 验收标准

- 新建场景/载入预设后，能在 1 分钟内完成“加 4 个推进器 → 调整朝向 → 观察变化”的演示。

## 2.2 Simulation Core（物理）补齐差异化

### 任务清单

- [ ] 重心 Center of Mass 可调（来自拼装参数或组件参数）
- [ ] 浮心 Center of Buoyancy 可调且影响姿态稳定性
- [ ] 推进器布局影响力矩：推进器推力产生的力矩计算正确、可见差异

### 验收标准

- 两套不同布局（例如对称 vs 不对称）在相同输入下表现明显不同（偏航、翻滚或漂移）。

## 2.3 基础状态输出（ROVState）稳定

### 任务清单

- [ ] 仿真循环中生成状态快照（每物理帧或固定采样点）
- [ ] depth 的定义/符号/参考面统一，并能在 UI 显示为正数深度（按项目需要）

### 验收标准

- 深度、姿态、速度等数值在静止/匀速/转向情况下行为合理（无明显跳变、单位正确）。

# 3. Phase C：P1 核心（专业感来源：数据记录 + 实时图表 + Dashboard）

> 这是 target.md 明确的“最应该投入精力的部分”。这里按依赖顺序组织：先有稳定采样与缓存，再做图表与面板。

## 3.1 Data Recorder（数据采集/缓存）

### 任务清单

- [ ] Recorder 节点/脚本：支持 Start/Stop
- [ ] 支持固定频率采样（例如 10Hz/50Hz），与物理帧解耦（定时器或累计 dt）
- [ ] 维护滑动窗口缓存（例如最近 N 秒），给图表实时渲染用
- [ ] 维护全量记录缓冲（可选，给回放/导出用）
- [ ] 统一 DataFrame 结构（time + state + thrusters[]）

### 验收标准

- 开启记录后：缓存长度与时间轴增长符合预期；关闭记录后：不再增长。
- 采样频率改变时：同一段时间内的记录点数量随之变化。

## 3.2 Dashboard（实时数值面板）

### 任务清单

- [ ] 基础数值：Depth / Velocity / Roll Pitch Yaw / Angular Vel（按需）
- [ ] 推进器状态列表：每个推进器的 command / thrust
- [ ] 刷新节流：UI 更新频率与采样频率一致或更低（避免每帧刷新导致抖动）
- [ ] 数值格式化：单位、保留小数位、角度显示为度

### 验收标准

- 面板在静止时稳定不闪；运动时能反映趋势；推进器输入变化时 thrust 跟随变化。

## 3.3 Real-time Charts（实时图表系统）

### 必做图表（与 target.md 对齐）

- [ ] 深度 depth vs time
- [ ] 姿态 roll/pitch/yaw vs time
- [ ] 推进器 thrust vs time（支持多条曲线：T1..Tn）
- [ ] 速度曲线（至少 linear speed 或 xyz 三轴）

### UI 行为要求（与 target.md 对齐）

- [ ] 平滑曲线（避免锯齿/跳点，至少做线性连接与抗抖动显示）
- [ ] 自动滚动时间轴（滑动窗口）
- [ ] 多曲线叠加（含图例/颜色区分）
- [ ] 可开关显示（按曲线组或单条）

### 技术实现建议（以 Godot UI 组件为基线）

- 渲染策略：
  - 首选：用自绘（Control._draw + draw_polyline）或 Line2D（放在 CanvasLayer/UI）实现折线图
  - 数据量控制：对窗口内点数做限额（例如最多 500~2000 点），超出则下采样
- 坐标映射：
  - X：time_s 映射到控件宽度
  - Y：自动量程（min/max + margin）或固定量程（由用户选择）

### 验收标准

- 开启记录后，曲线连续滚动；切换显示项不影响仿真稳定性；窗口内点数稳定且帧率可接受。

# 5. Phase E：P2（展示杀手：记录回放 + 设计评估 + 预设）

## 5.1 记录 & 回放

### 任务清单

- [ ] 保存一次记录为资源/文件（格式先内部可用即可：JSON/二进制均可，优先简单）
- [ ] 回放模式：时间轴推进，驱动物体姿态/位置（或驱动 UI 与可视化对齐）
- [ ] 回放同步图表：回放时图表显示同一段数据并支持拖动定位（可选）

### 验收标准

- 能完成演示台词：先跑一段测试 → 保存 → 立刻回放并同步看到曲线。

## 5.2 设计评估（自动分析输出）

### 任务清单

- [ ] 稳定性指标：翻滚/大角速度/姿态发散检测（阈值可配置）
- [ ] 对称性检查：推进器布局与方向的几何对称性粗判
- [ ] 重心合理性：重心偏移过大/浮心-重心相对位置提示
- [ ] 输出评估面板：✔/⚠ 列表 + 简短建议

### 验收标准

- 对“不稳定预设”能给出至少 1~2 条明确警告；对“稳定预设”输出以通过项为主。

## 5.3 预设方案（Demo）

### 任务清单

- [ ] 稳定 ROV 预设：对称推进器 + 合理重心/浮心
- [ ] 不稳定 ROV 预设：不对称布局或浮心偏移
- [ ] 高推力版本预设：快速加速/明显水动力效果
- [ ] 一键切换：载入预设后自动刷新拼装、仿真参数、UI

### 验收标准

- 演示时无需手工拼装也能在 10 秒内切换三种效果，并得到明显对比。
