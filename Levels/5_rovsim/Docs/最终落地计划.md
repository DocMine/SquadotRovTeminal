# ROVSim 最终落地计划

生成日期：2026-05-04

本文是 ROVSim 的产品级与工程级落地计划。它替代早期粗略路线，作为后续开发、审查和验收的主计划。实现必须遵守 `Docs/Godot工程通用要求.md`：场景优先、组件复用、显式类型、禁止 `:=`、中文优先本地化、文件操作使用系统对话框并显示绝对路径。

---

## 1. 产品定位

ROVSim 的目标不是做一个“能动的 Godot Demo”，而是做一个面向教学、展示和方案验证的 **ROV 设计、装配、仿真、数据分析一体化工具**。

V1 要做到：

- 能设计推进器与整机装配。
- 能保存/加载机器、推进器、仿真预设、图表布局和记录数据。
- 能清楚解释“机器为什么这样动”：推进器力、浮力、重力、阻力、合力、力矩都可视化。
- UI 看起来像成熟商业工程软件：有工作区、项目资源、属性检查器、数据面板、可停靠/切换的大图表视图，而不是所有图表挤在底部。
- 数据有明确去向：用户知道记录保存在哪里、当前记录有多少帧、采样频率是多少、是否已保存。

## 3. 最终工作流

### 3.1 项目工作流

1. 新建或加载项目。
2. 在资源库选择推进器模板、机体模板、控制模板。
3. 进入推进器设计器，编辑推进器外观、参数和推力曲线。
4. 进入整机装配器，放置推进器、设置方向、重心、浮心、质量和外形。
5. 运行仿真，观察 3D 运动、力矢量、Dashboard 和实时图表。
6. 开始记录，保存记录文件。
7. 回放记录，查看图表、数据表、关键指标和评估结果。
8. 保存机器预设、图表布局和完整项目。

### 3.2 用户必须明确看到的信息

- 当前项目文件路径。
- 当前机器配置文件路径。
- 当前推进器模板路径。
- 当前记录文件路径。
- 当前图表布局文件路径。
- 记录状态：未记录 / 记录中 / 已停止 / 未保存 / 已保存。
- 采样频率、记录时长、记录帧数、滑动窗口长度。
- 力图例：红色推进器力、绿色浮力、黄色重力、蓝色阻力、白色合力、紫色力矩。

## 4. 文件与数据格式

所有保存/加载入口必须使用 `ui_modules/FileDialogPanel` 或同等系统文件对话框模块，并显示系统绝对路径。

### 4.1 推荐目录

```text
user://rovsim/
  projects/
  machines/
  thrusters/
  chart_layouts/
  records/
  exports/
```

UI 显示时必须通过 `ProjectSettings.globalize_path()` 转换为系统绝对路径。

### 4.2 文件类型

- `.rovproj.json`：项目文件，保存工作区引用、最近打开的机器、记录、图表布局。
- `.rovmachine.json`：整机装配文件，保存机体、推进器实例、质量、重心、浮心、水动力参数。
- `.rovthruster.json`：推进器模板文件，保存推进器外观和物理参数。
- `.rovchart.json`：图表布局文件，保存图表页、曲线、颜色、单位、窗口长度、量程设置。
- `.rovrecord.json`：记录文件，保存 DataFrame 序列、机器摘要、采样频率、单位约定。
- `.csv`：数据导出文件，供 Excel/MATLAB/Python 分析。

### 4.3 JSON 版本字段

每个 JSON 必须包含：

```json
{
  "schema": "rovsim.machine",
  "version": 1,
  "created_at": "2026-05-04T00:00:00Z",
  "units": {
    "length": "m",
    "force": "N",
    "torque": "N*m",
    "angle": "rad",
    "time": "s"
  }
}
```

### 4.4 数据服务模块

新增目录：

```text
scripts/io/
  json_file_service.gd
  machine_serializer.gd
  thruster_serializer.gd
  record_serializer.gd
  chart_layout_serializer.gd
  csv_exporter.gd
```

职责：

- UI 只发出保存/加载请求。
- Serializer 负责 Dictionary 与业务对象互转。
- FileService 负责读写文件、错误处理、绝对路径转换。

## 5. 商业软件式 UI 信息架构

当前“四张图表挤在底部”的布局必须替换。目标是工作台式界面。

### 5.1 总体布局

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部工具栏：项目 / 机器 / 推进器 / 记录 / 图表 / 运行状态    │
├──────────────┬───────────────────────────────┬─────────────┤
│ 左侧资源库    │ 中央工作区                       │ 右侧检查器   │
│ Project Tree │ 3D View / Assembly / Charts     │ Inspector   │
│ Assets       │ Data Table / Playback           │ Properties  │
├──────────────┴───────────────────────────────┴─────────────┤
│ 底部状态栏：文件路径、采样率、记录帧数、FPS、告警            │
└────────────────────────────────────────────────────────────┘
```

### 5.2 顶部工具栏

功能：

- 新建项目、打开项目、保存项目、另存项目。
- 打开机器、保存机器。
- 打开推进器模板、保存推进器模板。
- 开始/暂停/重置仿真。
- 开始/停止记录、保存记录、导出 CSV。
- 加载/保存图表布局。

组件要求：

- 使用 `ActionButton` 做操作按钮。
- 使用 `StatusBadge` 显示运行状态和记录状态。
- 文件路径入口使用 `FileDialogPanel` 或其页面级组合。

### 5.3 左侧资源库

分组：

- 项目文件。
- 机器预设。
- 推进器模板。
- 记录数据。
- 图表布局。

交互：

- 双击加载。
- 右键或按钮：保存副本、删除、重命名。
- 选中资源时右侧 Inspector 显示摘要。

### 5.4 中央工作区

使用 Tabs：

- `3D 仿真`：大视口，力矢量、图例、相机控制。
- `整机装配`：推进器列表、3D 装配视图、变换工具。
- `推进器设计`：推进器外观、参数、推力曲线。
- `图表分析`：单张或多张大图表，可切换图表页。
- `记录回放`：时间轴、播放控制、数据表。
- `评估报告`：稳定性、对称性、推力冗余、重心/浮心建议。

### 5.5 右侧 Inspector

选中不同对象时显示：

- 机器：质量、体积、重心、浮心、阻力系数、角阻尼。
- 推进器实例：位置、旋转、方向、最大推力、当前命令、模板引用。
- 推进器模板：外观、半径、长度、颜色、推力参数、响应时间。
- 图表：曲线列表、颜色、单位、量程、窗口长度。
- 记录：文件路径、时长、帧数、采样率、机器摘要。

### 5.6 图表区域改造

图表不再固定挤在底部。改为：

- 中央工作区 `图表分析` Tab 中显示大图表。
- 默认提供四个图表页：
  - 运动总览：深度、速度、姿态。
  - 力与力矩：推进器力、浮力、重力、阻力、合力、合力矩。
  - 推进器监控：每个推进器 command、thrust、效率。
  - 稳定性：roll/pitch/yaw、角速度、姿态误差。
- 每页支持单图最大化。
- 支持图表布局保存/加载。
- 底部只保留一个小型趋势条或最近状态，不再塞四张完整图。

## 6. 推进器设计器

### 6.1 推进器模板数据

新增模型：

```text
scripts/model/
  thruster_template.gd
```

字段：

- `template_id: String`
- `display_name: String`
- `manufacturer: String`
- `model_name: String`
- `max_forward_thrust_n: float`
- `max_reverse_thrust_n: float`
- `response_time_s: float`
- `dead_zone: float`
- `efficiency: float`
- `power_w: float`
- `diameter_m: float`
- `length_m: float`
- `body_color: Color`
- `axis_color: Color`
- `propeller_color: Color`
- `force_axis_local: Vector3`
- `thrust_curve: Array[Vector2]`

### 6.2 推进器外观设置

可编辑：

- 外壳形状：圆柱、短舱、喷口。
- 半径、长度、喷口长度。
- 外壳颜色、轴线颜色、螺旋桨颜色。
- 显示比例。
- 推力方向箭头样式。

落地方式：

- `scenes/rov/thruster.tscn` 保留固定节点结构。
- `ROVThruster` 从 `ThrusterTemplate` 读取外观参数并更新 Mesh/材质。
- 推进器设计器只修改模板，不直接改装配实例。

### 6.3 推进器物理参数

可编辑：

- 最大正推力、最大反推力。
- 命令范围 -1..1。
- 死区。
- 响应时间。
- 推力曲线。
- 功率与效率。

推力计算：

```text
raw_command -> dead_zone -> response smoothing -> thrust_curve -> thrust_n
```

### 6.4 推进器设计器 UI

页面结构：

```text
推进器设计
  左：模板列表
  中：推进器预览 + 推力方向
  右：参数 Inspector
  下：推力曲线图
```

必须支持：

- 新建模板。
- 从文件加载模板。
- 保存模板。
- 另存为模板。
- 应用到当前选中推进器实例。

## 8. 力与力矩可视化

### 8.1 必须绘制的力

- 推进器力：红色，每个推进器一条。
- 浮力：绿色，从浮心发出。
- 重力：黄色，从重心发出。
- 阻力：蓝色，从机体中心或阻力中心发出。
- 合力：白色，从机体中心发出。
- 合力矩：紫色，用环形箭头或旋转轴线表示。

### 8.2 图例

3D 视图右下角或左下角显示固定图例：

```text
红色：推进器力
绿色：浮力
黄色：重力
蓝色：阻力
白色：合力
紫色：力矩
```

图例必须可折叠，不遮挡主要视图。

### 8.3 可视化控制

Inspector 或图层面板提供：

- 显示/隐藏所有力。
- 单独显示/隐藏推进器力、浮力、重力、阻力、合力、力矩。
- 力线缩放系数。
- 最小显示长度。
- 颜色设置。
- 显示数值标签。

### 8.4 数据结构

新增：

```text
scripts/sim/force_sample.gd
scripts/sim/force_snapshot.gd
```

字段：

- `force_type`
- `label`
- `origin_m`
- `vector_n`
- `torque_nm`
- `color`
- `source_id`

仿真核心每帧输出 `ForceSnapshot`，UI 和 Recorder 消费它。

### 8.5 记录要求

记录文件中保存：

- 每帧 ROVState。
- 每帧 ThrusterState。
- 每帧 ForceSnapshot。

这样回放时力线和图表可同步复现。

## 11. 评估报告

### 11.1 必做指标

- 最大深度。
- 最大速度。
- 最大角速度。
- 最大 roll/pitch。
- 是否翻滚。
- 稳定恢复时间。
- 推进器布局对称性。
- COB 是否高于 COM。
- 合力矩峰值。
- 推力冗余：某单个推进器失效时是否仍有基础前进能力。

### 11.2 输出形式

评估报告 Tab：

- 通过项。
- 警告项。
- 严重问题。
- 建议操作。

示例：

```text
警告：浮心与重心高度差不足，姿态恢复弱。
警告：右后推进器最大推力高于对侧 70%，偏航趋势明显。
通过：记录期间最大深度未超过安全阈值。
```

## 13. 实施阶段

### Phase 0：修正当前原型基础

目标：让当前版本不再像 Demo，而是具备工作台雏形。

任务：

## 17. V2：工程级仿真增强计划

V2 的目标是在 V1 闭环之上，把 ROVSim 从“设计与演示工具”推进到“工程验证原型工具”。V2 不追求一次性替代 Gazebo/Stonefish，但必须形成可保存、可记录、可回放、可分析的高保真扩展主路径。

### 17.1 V2 完成标准

- 海流与水动力参数会真实参与仿真，改变参数后运动、阻力、力图和图表会变化。
- 仿真帧中包含传感器数据：IMU、深度计、罗盘、DVL、USBL/GPS 类位置观测。
- 控制系统提供至少手动、定深、定航向、稳定辅助四种模式，控制命令可记录并显示。
- 记录文件保存状态、推进器、力、传感器、控制器、环境摘要。
- 评估报告能基于 V2 数据输出稳定性、传感器健康、控制误差、海流影响、推进器余量等结论。
- UI 中有明确的 V2 工程参数区：环境/海流、控制器、传感器、任务目标。
- 所有新增用户可见文本进入 `locale/ui_translations.csv`，编辑器内默认显示 `zh_CN` 文案。

### 17.2 高保真水动力

必须实现：

- 流体相对速度：阻力计算使用 `body_velocity - current_velocity`。
- 线性阻尼与二次阻尼同时存在，参数可配置。
- 角阻尼继续支持三轴差异，并输出力矩到 `ForceSnapshot`。
- 海流模型支持恒定流、深度分层流和简化扰动。
- 水动力摘要进入 Dashboard、图表和记录。

验收：

- 将海流 X/Z 从 0 调到非零后，ROV 在相同推进器命令下出现可观察漂移。
- 阻力曲线和力矢量随相对速度变化。

### 17.3 传感器系统

必须实现：

- `SensorSuite` 统一输出传感器帧。
- IMU：加速度、角速度、姿态。
- 深度计：深度、噪声、延迟占位字段。
- 罗盘：航向。
- DVL：相对水体速度。
- USBL/GPS 类定位：位置观测。
- 传感器数据进入记录和 CSV/JSON。

验收：

- Dashboard 能看到传感器摘要。
- 记录回放时传感器数据能复现。

### 17.4 控制系统

必须实现：

- 手动模式：使用用户给定推进器命令。
- 定深模式：以目标深度与当前深度误差计算命令。
- 定航向模式：以目标航向误差计算差动/等效命令。
- 稳定辅助：基于 roll/pitch/yaw 角速度压制命令。
- 控制器状态进入记录和报告。

验收：

- 切换模式后，同一目标值会改变推进器命令或控制状态。
- 目标深度/航向误差能在 UI 与报告中看到。

### 17.5 任务与环境场景

必须实现：

- 任务目标：目标深度、目标航向、目标速度。
- 当前任务状态：未开始、执行中、达成、偏离。
- 环境参数可保存到项目/记录摘要。

V2 可暂不做复杂地形和声呐，但数据结构必须为 V3 预留障碍物、航点和传感器扩展字段。

### 17.6 装配器增强

必须实现：

- 推进器布局分析：几何对称性、推力余量、偏航/俯仰/横滚力矩风险。
- COM/COB 合理性检查升级为量化指标。
- 当前装配导出的 `.rovmachine.json` 必须保留 V2 水动力参数字段。

### 17.7 图表、回放和报告增强

必须实现：

- 图表新增海流、传感器、控制误差曲线。
- 回放时间轴驱动 3D、力矢量、传感器摘要、控制器摘要同步变化。
- 评估报告新增：
  - 最大控制误差。
  - 最大传感器偏差。
  - 海流漂移风险。
  - 推进器饱和比例。
  - 角速度峰值和姿态恢复建议。

### 17.8 外部接口预留

V2 只做接口结构，不强制接通完整外部生态：

- 预留串口/UDP/TCP 数据入口。
- 预留 MAVLink/ArduSub/QGroundControl 接入模块目录。
- 预留 ROS2 桥接数据结构。

不允许为了外部接口破坏 V1/V2 的本地闭环；外部接口必须是可选能力。

### 17.9 V2 当前落地映射

本阶段执行时，V2 必须至少落地为以下工程对象，重新按计划执行时不得只停留在 UI 占位：

- 数据模型：
  - `scripts/sim/environment_state.gd`：记录海流模式、海流速度、相对水速、线性/二次阻尼和水密度。
  - `scripts/sensors/sensor_frame.gd`：记录 IMU、深度计、罗盘、DVL 与位置观测摘要。
  - `scripts/sensors/sensor_suite.gd`：统一生成传感器帧，后续传感器噪声、延迟和失效模型必须优先在这里扩展。
  - `scripts/control/control_state.gd`：记录控制模式、目标值、误差、辅助力/矩和推进器饱和比例。
  - `scripts/integration/external_interface_registry.gd`：保留 UDP/TCP/MAVLink/ROS2 外部接口状态结构，默认不启用，不破坏本地闭环。
- 仿真核心：
  - `ROVController` 的阻力计算必须使用 `body_velocity - current_velocity`。
  - 线性阻尼和二次阻尼必须同时参与阻力。
  - 手动、定深、定航向、稳定辅助四种控制模式必须可切换，且会改变控制状态或施加可视化辅助力/矩。
  - 控制状态必须包含任务状态：未开始、执行中、达成、偏离。
  - `DataFrame` 必须同时包含状态、推进器、力、环境、传感器和控制数据。
- UI：
  - “整机装配”栏目必须提供环境/海流与控制系统参数入口。
  - 右侧 Inspector 必须显示海流速度、相对水速、传感器深度/航向、控制误差和辅助力/矩。
  - “图表分析”必须包含 V2 工程状态图，至少显示海流、传感器深度、控制误差和辅助力。
- 数据闭环：
  - `.rovrecord.json` 必须保存 V2 数据帧。
  - CSV 导出必须包含海流、传感器、控制误差、辅助力/矩和推进器饱和比例。
  - 回放时必须恢复力图、Dashboard 与 V2 摘要。
- 评估报告：
  - 必须包含海流风险、控制误差和推进器余量判断。
  - 这些判断必须来自当前仿真或回放数据，不能是固定说明文案。

## 18. V3：Godot 风格整机装配编辑器深化计划

当前推进器布局暴露出一个关键问题：默认机器只有水平推进器，推进器方向基本朝向机器前方，用户无法通过装配改变机器深度控制能力。V3 的目标是把“整机装配”从参数表升级为接近 Godot 3D 编辑器的装配工作区，让用户可以导入机体框架、选择推进器、调整位置和朝向，并立即看到推力方向与深度控制能力变化。

### 18.1 装配编辑器完成标准

- 默认可加载的机器必须包含水平推进器和垂直推进器，启动后不再是“只能前后移动”的布局。
- “整机装配”栏目必须支持选择推进器实例，并编辑位置 X/Y/Z、旋转 Roll/Pitch/Yaw。
- “整机装配”栏目必须支持与 3D 仿真页一致的视角旋转、平移、缩放，便于观察装配结果。
- 推进器旋转改变后，3D 推力线、力图、保存文件和仿真受力必须同步改变。
- 机器框架可以通过文件入口导入，导入路径必须显示为系统绝对路径，并保存进 `.rovmachine.json`。
- 重新加载机器后，框架路径、推进器位置和推进器朝向必须恢复。
- UI 文案继续遵守本地化要求；场景内固定文本显示中文，运行时走 `locale/ui_translations.csv`。

### 18.2 编辑器式交互分层

落地顺序分三层推进：

- V3.1 数值装配编辑：推进器列表选择、位置/旋转 SpinBox、添加/删除、保存/加载。这是必须先完成的稳定底座。
- V3.2 视图辅助：选中推进器高亮、局部推力方向箭头、网格/坐标轴/重心/浮心提示、装配能力摘要。
- V3.3 直接操纵：在 3D 视图中使用移动/旋转 Gizmo 拖拽推进器，行为向 Godot 3D 编辑器靠拢。

当前阶段先完整实现 V3.1，并为 V3.2/V3.3 留出数据和接口。

### 18.3 机器框架导入

必须支持：

- 在“整机装配”栏目中提供“导入框架”和“清除框架”入口。
- 支持 `.glb` / `.gltf` 作为主要导入格式；允许后续扩展 `.obj`、`.stl`、`.mesh`。
- 导入框架挂载在 ROV 刚体下，仅作为可视化框架，不替代当前碰撞盒。
- 保存机器时记录 `frame_model_path`。
- 加载机器时若路径有效，应恢复框架显示；若路径失效，应保留路径并给出状态提示。

### 18.4 推进器实例编辑

每个推进器实例必须具备：

- 可选中：列表选中与 3D 高亮同步。
- 可编辑位置：X/Y/Z，单位 m。
- 可编辑旋转：Roll/Pitch/Yaw，UI 使用 deg，保存仍使用 rad。
- 可查看推力方向：由 `global_transform.basis * local_force_axis` 决定。
- 可保存：位置、旋转、推力轴、最大推力随机器文件保存。

编辑后必须立即：

- 更新 3D 中推进器位置和朝向。
- 更新推力方向线。
- 更新装配报告中的布局能力判断。
- 标记当前机器配置为需要保存。

### 18.5 深度控制能力检查

评估报告必须新增装配级判断：

- 垂直推力能力：统计推进器世界推力方向在 Y 轴上的分量。
- 水平推力能力：统计 X/Z 平面推力能力。
- 若垂直推力能力过低，报告必须明确提示“当前推进器布局无法有效改变深度”。
- 若所有推进器几乎同向，报告必须提示“姿态/深度控制自由度不足”。

### 18.6 默认预设修正

内置稳定与高推力预设必须从 4 推进器升级为至少 6 推进器：

- 4 个水平推进器负责平面运动和偏航。
- 2 个垂直推进器负责上浮/下潜。
- 垂直推进器的旋转必须让 `local_force_axis = (0, 0, -1)` 映射到世界 Y 方向。

不稳定预设可以保留不良布局，但必须能体现“垂直控制不足”或“不对称”的评估警告。
